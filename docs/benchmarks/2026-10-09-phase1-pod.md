# Phase 1: reads from a pod with a Flaminio volume (2026-10-09, step 8)

fio in a Kubernetes pod on a 16 GiB Flaminio volume, through the whole phase-1 stack, against
fio on the node's raw data disk:

```
CSI (raw block PVC) → ublk → flaminio-io node (engine, verified replication core) → replica store → /dev/vdb
```

Reads only ([the reads-only rule](2026-10-08-store-baseline.md)). Same hardware as
[the raw baseline](2026-10-08-raw-baseline.md); the node is fl-b (NVMe).

## Method

- `make bench-pod NODE=fl-b RUNTIME=30` ([`deploy/lab/bench-pod.yaml`](../../deploy/lab/bench-pod.yaml)).
- **The volume:** 16 GiB, RF 2, 64 chunks of 256 MiB, as a raw block device in the pod.
  - With CSI topology, the metadata service placed a replica of all 64 chunks on fl-b, the
    pod's node, so reads are local.
  - The other replicas are on fl-c, across the 1 GbE link.
- **The pod** writes the whole volume once (1 MiB writes, depth 32), then runs the read jobs:
  30 s each after 3 s of ramp-up, fio `io_uring`, `direct=1`. fio is a static build of
  fio-3.41.
- **The raw disk** is read right after, with the same jobs (`fio-raw.sh`), read-only.
- **Repetitions:** one run of each per session; two sessions. This is a phase-1 check, not a
  campaign: the MVP campaigns had three interleaved repetitions. The JSON of the second session
  is in [`data/2026-10-09-pod/`](data/2026-10-09-pod/).

## Results

| Read job | Pod, session 1 | Pod, session 2 | Raw, session 2 | Pod/raw (session 2) |
|---|---:|---:|---:|---:|
| 4K random, QD1 | 12 993 IOPS, p99 84 µs | 12 681 IOPS, p50 76 µs, p99 87 µs | 13 854 | **91%** |
| 4K random, QD32 | 183 827 IOPS, p99 264 µs | 184 134 IOPS, p99 268 µs | 266 507 | **69%** |
| 1M sequential, QD8 | 3 817 MiB/s | 3 456 MiB/s | 6 277 | **55%** |

Writes, indicative only: the fill ran at 107 MiB/s, the 1 GbE link to the remote replica.

## What it shows

- **Kubernetes adds nothing measurable.** The pod's numbers match the same jobs on the node's
  device earlier the same day (12 740, 184 000 and 3 130 MiB/s, [phase 1 plan](../phase1-plan.md)).
  CSI only sets up the device.
- **QD1 is at 91% of raw.**
- **QD32 and 1M are where the work is.** At QD32 the phase-1 path reaches 69%, below the MVP
  frontend's 86% (219k IOPS, [ublk reads](2026-10-08-ublk-reads.md)): the engine's per-I/O
  bookkeeping costs CPU on the single queue thread. 1M sequential is CPU-bound on that thread,
  as in the MVP.
- Both are [follow-ups](../followups.md) item 1: trimming the per-I/O path, several ublk queues,
  zero-copy.
