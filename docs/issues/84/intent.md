# Issue #84: Validate the exported block durability contract — intent

[GitHub issue](https://github.com/jsfakian/Flaminio/issues/84). This plans the durable frontend
contract and its conformance evidence; it does not implement write-back or replicated discard.

## Why

- `dataplane/crates/flaminio-io/src/ublk.rs:953` advertises 4 KiB logical blocks and no volatile
  cache. Both node queue implementations complete FLUSH/DISCARD with success as no-ops
  (`ublk.rs:1279,1454`). FUA must not weaken ordinary durable-write completion.
- `Engine::submit` (`flaminio-node/src/engine.rs:1685`) splits requests at chunk boundaries;
  `sub_done` waits for all pieces but cannot roll back a piece that landed before another failed.
  The core simulator's checker is per block (`flaminio-repl/src/sim/check.rs:32`).
- `Target::check_write` waits for the effective quorum; pending ISR shrink/expansion semantics
  must survive any frontend refactoring (`flaminio-repl/src/target.rs:1421,1605`).
- Store `start_commit`/checkpoint ordering explicitly flushes persistence. Device branding does
  not establish equivalent durability through controllers or VM caches.
- Storage CRCs are generated by the receiver; `Frame::Write` has no target checksum field.
  The design must not advertise target-to-store checksums as an existing feature.
- The audit at `10265b6` proposes ADR0010 and records missing real frontend conformance evidence.
  Kernel io_uring lifetime issue #85 is a separate prerequisite, not proof of a FLUSH bug here.

## What we want

1. Publish and test one precise durable per-block contract for the supported ublk modes.
2. Make flags, queue ordering, partial completion and retry behavior match that contract.
3. Retain discard as a hint until a separately modelled, fenced implementation exists.
4. Separate host-model tests from actual kernel/device evidence and record unsupported cases.

## Out of scope

- Write-back, multi-block transactions, target-generated checksum framing (#46/#50), snapshot
  implementation (#51), generic QoS (#75), geometry admission (#80), or fixing #85 here.
- Running shared-lab, privileged ublk or power-cut tests during planning. This issue stays open
  until the required frontend evidence exists, even if documentation and local models pass.
